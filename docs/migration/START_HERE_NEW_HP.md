# Начать здесь на новом HP

На флешке находится полный переносной комплект Auto Monitor Bot. Ничего со старого ноутбука удалять не нужно.

## Важные правила

1. Сначала скопировать весь каталог `AUTO_MONITOR_BOT_TRANSFER` с флешки на внутренний SSD HP.
2. Проверить `checksums\SHA256SUMS.txt` встроенным PowerShell до запуска установщиков и распаковки архивов.
3. Не запускать production-мониторинг, пока старая копия работает.
4. Не копировать `node_modules`, живой `pgdata` или Redis AOF со старого ноутбука.
5. Не помещать `.env`, Telegram token, API keys или Android keystore в Git.
6. Не обновлять версии Node, pnpm, PostgreSQL, Redis, Prisma или других зависимостей во время миграции.

## Содержимое

- `project`: полный Git bundle и архив текущего рабочего дерева со всеми незакоммиченными изменениями.
- `database-backups`: зашифрованный логический PostgreSQL dump и контрольные файлы.
- `secrets-encrypted`: отдельный зашифрованный архив `.env` и Android signing-файлов.
- `runtime-installers`: PostgreSQL 18.6, автономные Node.js 24.18.0/pnpm 10.34.5 и Redis 8.8.0.
- `tool-installers`: официальные установщики Git, 7-Zip и Tailscale с SHA-256 и цифровыми подписями.
- `task-scheduler`: XML старого компьютера только для сравнения. Не импортировать вслепую.
- `docs`: аудит, манифест, настройка, переключение и откат.
- `CODEX_HANDOFF_PROMPT.md`: готовая задача для Codex на HP.

## Что сделать пользователю

1. Открыть Codex на HP.
2. Передать ему файл `CODEX_HANDOFF_PROMPT.md` или вставить его содержимое в задачу.
3. Сообщить пароль `BACKUP_ENCRYPTION_PASSWORD` только в момент локальной распаковки. Не отправлять пароль в Git или публичный чат. Если пароль не сохранён отдельно, остановиться и получить его безопасно со старого ноутбука.
4. Подтвердить установку скачанных программ, когда Windows/Codex попросит подтверждение.

До финального переключения старый ноутбук остаётся единственным production producer.

# Регистрация и восстановление Telegram-подписчиков

13.10.2026. Подготовлено исправление поверх работающей ревизии 23b5e70; выпуск не выполнялся, сохраняется указание пользователя выпускать после третьего этапа.

## Найденные причины

1. При старте API `latestOffset()` читал накопившиеся updates и переходил за последний без обработки. `/start`, поступивший во время остановки API, терялся.
2. Offset увеличивался до успешной обработки: ошибка БД могла привести к подтверждению потерянной регистрации.
3. `/start` активировал подписчика, но оставлял его недоставленные receipts/bundles в PERMANENT после `chat not found` или блокировки.
4. Ожидание отправки приветствия блокировало обработку следующей регистрации, включая сетевой timeout и ожидание Telegram gate.

## Исправление

Накопившиеся updates обрабатываются; offset продвигается после успешной обработки. Подписка и восстановление известных permanent send failures сохраняются транзакционно. Принятые flash и карточки с messageId не сбрасываются. Pending работа передаётся в очередь сразу; повторный update восстанавливает передачу после сбоя Redis. Новому подписчику не рассылается вся старая история. Приветствие отправляется отдельно от регистрации с записью ошибки при неудаче.

## Проверка

Итоговый gate: **141 файл / 893 теста**, stderr пуст; typecheck всех пакетов, ESLint изменённых файлов и `git diff --check` прошли.

Регрессии: старт после остановки API; ошибка БД до acknowledgement; зависшее приветствие не задерживает второго подписчика; восстановление только нужного чата; правильная маршрутизация подробностей; повторная передача в Redis.

Расширенный `-TelegramOnly` стенд на изолированных PostgreSQL:57008 / Redis:57009 прошёл. Реально проверены восстановление PERMANENT после активации, отсутствие повторного сигнала другому получателю и доставка следующего объявления третьему новому подписчику. Telegram заменён локальным HTTP-сервером, production data не менялись, реальных сообщений не отправляли.

## Границы

Новый bot identity не получает права писать прежним пользователям автоматически. Получателю с `chat not found` необходимо открыть @AutoMonitorUABot и нажать «Запустить». До этого LIVE-доставка ему не исправлена. После выпуска кода /start позволит восстановить сохранившиеся недоставленные записи; удалённые retention записи этим механизмом не восстанавливаются.

Нулевая задержка не гарантируется: остаются polling источников, сеть и Telegram rate limits. Gate 1100 мс и первый сигнал перед подробностями сохранены. Миграция исторических message IDs между разными ботами — отдельный вопрос, этим изменением не решается.

Семантика acknowledgement проверена по [Telegram Bot API getUpdates](https://core.telegram.org/bots/api#getupdates): offset выше update_id подтверждает update. Поэтому offset нельзя увеличивать до успешного сохранения подписки.

# Глубокий аудит Auto Monitor Bot 0.4.1

Дата проверки: 22.08.2026.

## Итог

Локальный runtime проекта исправен и готов к постоянной работе. Корректирующий релиз 0.4.1 устраняет ложную статистику Dashboard, неполную историю запусков и инцидентов, ошибочные перезапуски watchdog при внешней блокировке источника и вводящие в заблуждение сообщения о доступности OLX.

Система работает в безопасном деградированном режиме: Cars.ua и AutoMoto продолжают мониторинг и немедленно передают подходящие объявления в общий hot handoff; OLX находится в `RATE_LIMITED`, RST — в `CAPTCHA_DETECTED`. Их cooldown сохраняется, агрессивные повторы и обход защиты отключены. Полную доступность OLX нельзя считать восстановленной до успешной одиночной контрольной попытки после окончания паузы.

| Область | Текущее состояние |
|---|---|
| Локальный runtime | API, PostgreSQL, Redis, worker, Dashboard и supervisor проходят обязательные проверки |
| Быстрый мониторинг | Все доступные источники используют раннюю обработку горячих кандидатов; Cars.ua работает с безопасным интервалом 15 ± 3 с |
| Защита источников | OLX/RST cooldown не сбрасывается вручную, watchdog не перезапускает здоровые процессы из-за внешней CAPTCHA/403 |
| Dashboard | «Сегодня» считается по уникальным обнаружениям с начала суток по Киеву; история и инциденты собираются отдельно для каждого источника |
| Тесты и сборка | 62 файла / 261 тест, TypeScript, ESLint, PowerShell validation, Prisma и production builds проходят |
| Покрытие тестами | statements/lines 30,81%, branches 73,35%, functions 46,81%; coverage gate включён |

Telegram-ограничение теперь является межпроцессной гарантией: API, hot/background workers и watchdog используют один атомарный Redis gate по bot/chat. Серверное время Redis исключает clock skew, Telegram `retry_after` продлевает общий cooldown, а секретная часть bot token не попадает в ключ.

## Исправления 0.4.1

1. `GET /sources/status` больше не берёт глобальные 20 запусков: API возвращает до восьми последних запусков каждого источника.
2. Для каждого источника всегда виден его актуальный активный инцидент, а закрытые ограничены отдельной историей из 20 записей.
3. Счётчик Dashboard «Сегодня» основан на уникальных `sourceSeenListing` с начала текущих суток в часовом поясе Киева, а не на сумме небольшого окна запусков.
4. Ручная проверка защищённого источника возвращает `409 SOURCE_PROTECTED`; повторное включение источника не стирает `pausedUntil`, счётчик ошибок и cooldown.
5. Состояние worker отделено от доступности внешних сайтов. Свежий heartbeat локального процесса остаётся здоровым, даже если источник законно находится в защитной паузе.
6. Watchdog перезапускает стек только при локальной неисправности. RATE_LIMITED/CAPTCHA/PAUSED создают отдельное редкое уведомление и не попадают в цикл recovery.
7. Планировщик и OLX collector больше не обещают работающий realtime при фактической защитной паузе.
8. System check получил отдельную проверку live-покрытия: доступные резервные источники отображаются как деградированная, но рабочая линия мониторинга.
9. Добавлены регрессионные тесты группировки истории, инцидентов, ручной проверки, OLX coverage-сообщений и fallback-портфеля.

## Скорость и защита от CAPTCHA

- Скорость выжимается внутри разрешённого окна: кандидаты обрабатываются сразу после получения, до тяжёлого enrichment и полной сверки.
- Cars.ua работает на 15 ± 3 с; AutoMoto — на 60 ± 10 с. OLX healthy cadence ускорен до 20 ± 4 с по измеренному p95 полного прохода 17,45 с, а после защиты автоматически возвращается через 60 ± 10 и 30 ± 6 с; это не воспроизводит прежний опасный 4-секундный режим.
- Для OLX действует возрастающий cooldown 6/12/24 часа и только одна контрольная попытка после его окончания.
- CAPTCHA, 403 и rate limit не обходятся. Проект не маскирует такие состояния как локальную неисправность и не создаёт шторм запросов.
- Исторические измерения 27.07.2026 (p95 4,92 с на 66 последовательных OLX-запусках без ошибок) относятся к прежнему доступному окну и не описывают состояние 22.08.2026.

## Текущая функциональная приёмка

- `.\amb.cmd check`: Prisma schema/client, документация, TypeScript, ESLint, PowerShell validation, 62 файла / 261 тест, coverage gate и изолированные production builds — успешно.
- Dashboard: Next.js 16.2.12 / Turbopack production build — успешно.
- Фильтр «OLX/RST боевой фильтр» сохраняет заданную географию Днепр/Днепропетровская область. За последние 24 часа резервные источники передали кандидатов, но они были корректно отклонены по географии/цене/пробегу; автоматически расширять пользовательский фильтр нельзя.
- Проверка OLX parity намеренно не запускается во время активной защитной паузы: она создала бы запрещённый дополнительный запрос.

## Архитектурные гарантии

- Каждый нормализованный кандидат записывается в observation journal до фильтрации.
- Неизвестные и отклонённые кандидаты можно replay-ить после изменения фильтра или нормализатора.
- Fast path отделён от фоновых coverage/backfill/enrichment запросов.
- Redis collector-lock продлевается владельцем во время длинного прохода.
- Все изменяющие Telegram-запросы проходят общий Redis rate gate; штатные API/worker-пути fail-closed при недоступном Redis, watchdog имеет узкий emergency fallback только для оповещения об отказе Redis.
- Ошибки дедуплицируются, очереди и per-source health доступны в системной диагностике.
- Production lifecycle управляется долгоживущим SYSTEM-supervisor и Windows-задачами.
- Backup шифруется AES-256, сопровождается SHA-256 и проверкой восстановления.

## Оставшиеся внешние ограничения

1. OLX сейчас не отдаёт стабильный разрешённый поток данных. Восстановление возможно только после успешной безопасной контрольной попытки; гарантировать отсутствие будущих CAPTCHA невозможно.
2. RST отвечает CAPTCHA. Проект сохраняет cooldown и не пытается обходить защиту.
3. Резервные источники не обеспечивают идентичное OLX-покрытие, но сохраняют рабочий мониторинг в период блокировки.
4. AutoMoto публикует время с ограниченной точностью, поэтому его latency менее точна.
5. Tailscale HTTPS недоступен для текущего аккаунта; доступ остаётся внутри шифрованного tailnet.
6. Физически независимый backup mirror не настроен: C: и D: находятся на одном диске, нужен внешний диск или UNC-путь.
7. Полный Telegram latency baseline ещё набирается; пустую или малую выборку нельзя выдавать за подтверждённый SLO.
8. Без официального event API ни один мониторинг не может математически гарантировать объявление, которое площадка не показала ни в одном разрешённом ответе.

## Рекомендация

Версия 0.4.1 готова к безопасной локальной эксплуатации в деградированном режиме Cars.ua/AutoMoto. Защитную паузу OLX/RST следует сохранить до планового одиночного probe; после его успеха система автоматически вернёт источник в рабочий цикл. Следующие инфраструктурные улучшения — внешний backup mirror и накопление достаточного Telegram latency baseline.

## Результат по OLX

### Скорость

- Основной OLX hot path сохранён на интервале **4 ± 1 секунды**.
- Планировщик просыпается с коротким шагом и запускает источник по ближайшему `nextCheckAt`, а не ждёт длинный общий цикл.
- Первое Telegram-сообщение сохраняется и отправляется до тяжёлого enrichment; дополнительная обработка не задерживает первичное уведомление.
- Realtime и backfill изолированы: глубокое восстановление не блокирует быстрый поток.

### Полнота

Для каждого поискового fingerprint независимо работают четыре слоя:

1. быстрый JSON feed;
2. regional coverage;
3. exact-city HTML coverage;
4. private-seller shadow feed.

Состояние каждого слоя хранится в PostgreSQL. Поэтому один активный фильтр больше не может «съесть» периодическую проверку другого через общую переменную процесса.

Последняя прямая контрольная сверка:

```text
213 из 213 непосредственно видимых ID уже присутствуют в search state или observation journal
fast feed:       163 ID
HTML coverage:   101 ID, из них 3 вне fast feed
private coverage:112 ID, из них 47 вне fast feed
```

Это подтверждает, что дополнительные lanes не декоративны: они обнаруживают объявления, которых в текущем быстром ответе нет, а локальная система их не потеряла.

Дополнительные гарантии проекта:

- каждый нормализованный кандидат пишется в observation journal до фильтрации;
- неизвестные и отклонённые кандидаты можно безопасно replay-ить после изменения фильтра/нормализатора;
- old/promoted карточка перед свежей не останавливает просмотр страницы;
- cutoff считается доказанным только при all-known выдаче или непрерывном известном хвосте;
- feed error и candidate overflow запрещают ложный anchor/cutoff;
- исчерпание realtime page budget создаёт явное предупреждение о возможном пробеле;
- HTML/private/regional cadence и результаты видны в `coverageMetrics` каждого запуска;
- CAPTCHA и rate limit переводят источник в cooldown с jitter/`Retry-After`, без агрессивного обхода защиты.

## Реализованные десять направлений апгрейда

1. **Windows lifecycle.** Основная задача запускает долгоживущий SYSTEM-supervisor от загрузки Windows до ручного выключения ноутбука. Повторные boot/logon trigger коалесируются lock-файлом.
2. **Корректный старт.** Фиксированное ожидание заменено readiness-проверкой API, PostgreSQL, Redis и dashboard с двумя стабильными подтверждениями.
3. **Полнота OLX.** Coverage cadence перенесён из глобальных переменных процесса в per-fingerprint состояние БД; добавлены regional, HTML и private lanes.
4. **Контроль пропусков.** Добавлены структурированные coverage metrics и повторяемый прямой `test:olx-parity`.
5. **Телеметрия.** Старые collector runs агрегируются почасово, ошибки дедуплицируются по fingerprint и считают повторения, retention выполняется транзакционно.
6. **Backup и disaster recovery.** Ежедневный AES-256 backup проверяется через `pg_restore --list`, `7z t` и SHA-256; добавлены внешний mirror и еженедельный restore drill.
7. **Безопасность.** Dashboard использует отдельный `DASHBOARD_AUTH_SECRET` и больше не принимает API token как session secret; production-зависимости очищены от известных high vulnerabilities.
8. **Платформа.** Next.js обновлён до 16.2.11, Prisma до 7.9.0 с PostgreSQL driver adapter; миграции применены, client generation входит в основную проверку.
9. **Android и удалённый доступ.** Собран подписанный APK 1.3.0, адрес ограничен приватным Tailscale tailnet; публичный HTTP и внешняя WebView-навигация запрещены.
10. **Поддерживаемость и очистка.** OLX scheduler и Telegram formatting выделены в отдельные модули; добавлены безопасная очистка generated/temp мусора, новые регрессионные тесты и актуальная документация.

- Очиститель ограничен project-generated архивами и пользовательским Temp старше 14 дней с проверкой разрешённых путей.
- Нужные dependency-архивы вроде JDK `src.zip` и SDK assets сохранены.

## Данные и резервное копирование

- Последний проверенный backup: `.runtime/backups/database-20260722-020556.7z`.
- Рядом хранятся JSON metadata и SHA-256.
- В текущей БД остаются 74 063 raw collector runs за retention-окно и 181 почасовой агрегат старой истории.
- 19 392 зарегистрированных error occurrences занимают 1 270 уникальных fingerprint вместо десятков тысяч повторяющихся строк.
- Legacy observations без `normalizedData` и orphan search states после compaction отсутствовали.
- `BACKUP_MIRROR_PATH` поддерживает другой локальный том или UNC. Копирование на тот же физический том намеренно запрещено как ложная резервная копия.

## Оставшиеся минусы и внешние ограничения

1. **Нельзя математически гарантировать ID, который сам OLX не показал ни в одном доступном ответе.** Без официального event API максимальная практическая защита — несколько независимых выдач, журнал, replay и регулярная parity-сверка. Всё это реализовано.
2. **RST сейчас отвечает CAPTCHA.** Проект корректно ставит cooldown и не атакует источник повторами, но легально устранить внешнюю CAPTCHA только локальным кодом нельзя.
3. **AutoMoto публикует время с ограниченной точностью.** Источник остаётся полезным резервом, но latency по нему менее точна, чем у OLX.
4. **Tailscale HTTPS недоступен для текущего аккаунта.** `tailscale cert` возвращает `your Tailscale account does not support getting TLS certs`; до изменения настройки остаётся HTTP внутри шифрованного tailnet.
5. **Single-host остаётся единой точкой физического отказа.** Внешний mirror поддержан, но `BACKUP_MIRROR_PATH` ещё нужно направить на отдельный накопитель/UNC.
6. **Нет Git remote.** Локальные workflow подготовлены, но GitHub-hosted CI нельзя подтвердить без подключения удалённого репозитория.
7. **Несколько доменных модулей всё ещё крупные.** Самые рискованные части OLX scheduling и Telegram formatting уже выделены, но дальнейшее дробление UI filters и vehicle-check улучшит сопровождение.
8. **Docker images закреплены major-tag, а не digest.** Это не влияет на текущий Windows runtime, но строгий воспроизводимый Docker deployment потребует digest pinning.

## Итоговая рекомендация

Текущий релиз **0.4.0 готов к постоянной локальной работе**. Следующий полезный шаг не связан с очередным ускорением запросов: подключить отдельный физический носитель/UNC для `BACKUP_MIRROR_PATH` и, если Tailscale-аккаунт разрешит HTTPS, пересобрать Android без cleartext. Остальные улучшения — плановая поддерживаемость, а не исправление текущей работоспособности.
